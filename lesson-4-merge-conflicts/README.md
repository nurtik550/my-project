## Цель
Научиться понимать причины конфликтов Git, находить конфликтующие участки, исправлять их вручную, завершать и отменять слияние.

## Задание 1. Конфликт в одном файле

Создан файл `message.py`. Ветка `feature-welcome` меняет приветствие на «Добро пожаловать в Python», а ветка `main` — на «Добро пожаловать на урок». При слиянии Git не может выбрать вариант автоматически.

После разрешения конфликта оставлен объединённый вариант:

```python
print("Добро пожаловать в Python и на урок!")
```

## Команды для воспроизведения конфликта

```bash
git init
git add .
git commit -m "Initial commit"

git switch -c feature-welcome
# Изменить message.py на print("Добро пожаловать в Python")
git add message.py
git commit -m "Update greeting in feature branch"

git switch main
# Изменить ту же строку на print("Добро пожаловать на урок")
git add message.py
git commit -m "Update greeting in main branch"

git merge feature-welcome
git status
# Исправить конфликт в редакторе и удалить маркеры
git add message.py
git merge --continue
git status
git log --oneline --graph --all
```

Если нужно отказаться от незавершённого слияния, используется:

```bash
git merge --abort
```

## Контрольные вопросы

1. **Что такое Merge Conflict?** Ситуация, когда Git не может автоматически объединить изменения из разных веток.
2. **Почему Git не всегда объединяет изменения автоматически?** Потому что разработчики могли по-разному изменить один и тот же участок, и Git не знает, какой вариант выбрать.
3. **Когда возникает конфликт?** Когда изменения пересекаются: одна строка изменена по-разному, файл удалён в одной ветке и изменён в другой и т. д.
4. **Что означает `<<<<<<< HEAD`?** Начало варианта из текущей ветки.
5. **Для чего нужен `=======`?** Разделяет два конфликтующих варианта.
6. **Что означает `>>>>>>> feature-message`?** Конец варианта из объединяемой ветки.
7. **Нужно ли оставлять маркеры?** Нет, их нужно удалить после выбора итогового кода.
8. **Для чего нужен `git add`?** Сообщает Git, что конфликт в файле исправлен и файл готов к коммиту слияния.
9. **Что делает `git merge --continue`?** Завершает слияние после разрешения конфликтов.
10. **Как отменить незавершённое слияние?** Командой `git merge --abort`.

## Полезные команды

| Команда | Назначение |
|---|---|
| `git status` | Показывает состояние репозитория |
| `git diff` | Показывает изменения |
| `git merge branch-name` | Объединяет ветку |
| `git add file.py` | Отмечает конфликт как исправленный |
| `git merge --continue` | Завершает слияние |
| `git merge --abort` | Отменяет незавершённое слияние |
| `git log --oneline --graph --all` | Показывает историю веток и коммитов |

**Вывод:** конфликт — нормальная часть совместной разработки. Git показывает спорные места, а разработчик выбирает правильный итоговый вариант, удаляет маркеры и завершает слияние.
